# Model prompting recipes and model choice

Before writing prompts for a model, the agent reads that model's recipe here (PB3 decision 5: prompts follow the target model's own guide). Each recipe records its sources and the date it was checked. A model without a recipe gets one before its first use: a model chosen on a Models page gets its recipe written into the workspace's `library/model-prompting/<owner>-<name>.md` (the title line `(checked YYYY-MM-DD)`, its `Sources:`, the input fields from Replicate's API). The recipes here are a head start, not a list of allowed models. Recipes stay per model; which model does what is not written here.

## Which model: the model registry (issue #115)
Every model, the variant the plugin sends, its price and its limits are in **the model registry**, `../../data/models/registry.yaml` (`tm models list --task <task>`), and nowhere else: no prose lists models or prices. Per task it holds a budget, a suggested and a best group, with one model selected in advance (★), and the routes that pick a model by situation (the talking person, the voice, a speech longer than one take). The owner tests each model before it enters; a review every two weeks (`.github/workflows/model-review.yml`) opens one issue for the owner with what is new, and nothing changes in the registry without the owner's decision.

1. **Suggest, do not impose.** The Models page (Organic AI video's E1, Create an ad's S5, Refresh an ad's D1) shows each task's groups from the registry, the ★ model ticked, each with its price per unit and its one sentence; the user may pick another or write their own model.
2. **Always send the variant.** Replicate's defaults are often the dear ones (MiniMax H3 defaults to 2K, GPT Image 2.5 and 2.6 to `quality: auto`, Wan 3 to 1080p): a call sends its variant's `send` inputs, so the price shown is what it costs.
3. **Live in a run: only price and availability**, from the model's Replicate page (`tm models ids --task <task>` names them, `tm tool replicate_price --run R <those ids>` reads them); rankings are read live only when the registry is older than 30 days.
4. **A model the user names** outside the registry is used without being blocked; its recipe is written first, and it is checked against the criteria below.
5. **One video model per video.** All clips of a video come from one model; another model only for a separate section (e.g. a Claude animation insert). A failed shot is regenerated on the same model; if the model fails the whole video, the whole video moves to another model.

## Seedance 2.0 and people (checked 2026-11-05)
On the API (Replicate, BytePlus) Seedance 2.0 rejects input images with a photorealistic human face, synthetic ones included (Replicate error E005 "flagged as sensitive", within ~5 s, no output); a retry with the same input fails the same way. The official route for a real face is a liveness check of that person and a verified asset, which does not apply to an AI host. So Seedance cannot take a realistic AI host as a first frame or reference; use MiniMax H3 for talking-host formats. Sources: ComfyUI Seedance 2.0 docs (https://docs.comfy.org/tutorials/partner-nodes/bytedance/seedance-2-0), laozhang.ai (https://blog.laozhang.ai/en/posts/seedance-2-api-real-people.md), APIYI face-asset FAQ (https://docs.apiyi.com/en/faq/seedance2-face-asset-whitelist.md). Bypass tricks (grids, resizing) are not used.

**Person described in text instead (tested 2026-11-05, PB3 P4 take_v07):** with no human photo in the inputs (references: product packshot + dog anchor only) Seedance 2.0 passes and gives a strong result: the product closest to 1:1 of all tests (arcs from the top edge, nub grid, suction cups), all 5 lines spoken incl. the quiet last line, a consistent creator across cuts, very natural phone look. Limits: the person is new each generation (a recurring host cannot be locked, since her frame cannot be fed back as a reference), cut times drift ±1.3 s from the brackets, extra product placement may appear (the mat on the counter in the opening shot), audio quieter (−18.6 LUFS, normalise in the edit).

**Official route for an AI host as a reference (researched 2026-11-05):** BytePlus ModelArk *Private virtual portrait library*: upload the AI portrait as a virtual-portrait asset (must not resemble a real person; security review), then pass `asset://<Asset_Id>` as `reference_image` (or first frame) in the Seedance 2.0 / 2.5 request. Needs a direct ModelArk account and Advanced Creation Rights (Entry tier free: 50 assets, 3 QPM); not available via Replicate. A real creator goes through the real-human portrait library (liveness + authorisation). Details and sources: `runs/03-organic-ai-video/2026-11-05_pet-dtc-proposals/02_research/models/seedance_faces_v01.md`. Detector-evasion tricks (grids, banners, crops) are not used.

**Confirmed by other users (2026-11-06):** the block is reported independently on GitHub (ComfyUI issue #13524, AI portrait rejected), Adobe Community (Firefly; an Adobe employee confirms Seedance 2.0 takes no human faces in references) and Reddit r/generativeAI. The user decided not to open a BytePlus account, so the asset route is not used; use the creator-in-text route or H3 reference mode. Evidence: `runs/03-organic-ai-video/2026-11-05_pet-dtc-proposals/02_research/models/seedance_faces_v02.md`.

## Talking AI person: which model (PB3 rounds 26–27, decided 2026-11-06; the models are the registry's since #115)
Applies to formats where a person who talks must be generated. **Which model** is the registry's talking-person route (`routes.talking_person`, by situation: exact wording, a specific person from an image, a person described in words, the user's or a brand voice, the fallback) and its voice route (`routes.voice`: who is on screen and whether the user has a recording). What the tests found:
- **H3 dialogue (round 47):** write the dialogue straight into the prompt; **no ElevenLabs voice reference by default** (it sounded worse and, in Polish, garbled words).
- **Off-screen narrator (round 45):** ElevenLabs voice by default (it sounds better than a model's own narrator).
- **A speech longer than one take:** several takes with the same reference image and the same voice, cut at a sentence end (`routes.long_speech`).
- **The user names another model:** check it against these criteria and say which one fails: photoreal AI person image accepted (only when a specific influencer is used); product enters from an image together with the person; native speech with lip sync (or the ElevenLabs + lip-sync route); 9:16; take length for the script (~2.5 words/s); available at the user's provider with a live price.
Comparison: `runs/03-organic-ai-video/2026-11-05_pet-dtc-proposals/02_research/models/host_frame_models_v01.md`.

## Resolution and upscaling (PB3 round 29, 2026-11-06)
- At the start of every generation (pack/cost gate) ask: **720p, 1080p, or 720p + upscale**, with the cost of each option for the chosen model.
- The upscalers, their variants and prices are the registry's `upscale` task. A model's own higher resolution (H3's 2K) can be cheaper than its base plus an upscale; the pack compares them.
- Upscaling must not change the sound; mux the original audio back with ffmpeg if needed. Comparison: `runs/03-organic-ai-video/2026-11-05_pet-dtc-proposals/02_research/models/upscale_models_v01.md`.

## Talking person in Create an ad (issue #95; the models are the registry's since #115)
Create an ad's rule CA5 (`skills/create-ad/references/rules.md`) uses the registry's talking-person route: the plan asks which situation applies **before the casting** (`presenter.situation` in the production plan, `tm ad check plan`), so no casting is paid for a face the model will not use (a model whose registry limits hold `photoreal_face` refuses one, E005). One speaker is one take whenever the lines fit the model's length, with the cuts between places described in the prompt; a next take keeps the same image and the same voice description. A weak native voice with the right lines and timing is changed with the Voice Changer (`tm tool elevenlabs sts`), which keeps the lip sync, before any new take. The recipes: [seedance-2.0.md](seedance-2.0.md), [minimax-h3.md](minimax-h3.md), [gemini-omni-1.2-flash.md](gemini-omni-1.2-flash.md), [kling-avatar-v2.md](kling-avatar-v2.md), [eleven-v4.md](eleven-v4.md).
